3. Add a process dynamically

A process can be appended to the current input set, then DBDAA can be run again. This models dynamic admission; it does not interrupt JavaScript execution mid-operation.

4. How DBDAA is represented

The implementation follows the paper’s described checks: compare each process’s maximum demand against total resources, calculate Need and Max_Need, sort the Ready Queue in ascending Max_Need, check resource positions using the marked/unmarked procedure, and track Safe, Primary Unsafe, and Unsafe sequences.

Implementation note: the paper describes a wall-clock timer and a wait state. A browser-only demo cannot reproduce a real operating-system scheduler, so the timer is represented as a configurable number of process checks per cycle. To prevent an endless loop when no resource state changes, the simulator limits retries and reports unresolved processes as Primary Unsafe at the end. Treat this as a documented educational translation of the paper, not a bit-for-bit reproduction of its runtime environment.
